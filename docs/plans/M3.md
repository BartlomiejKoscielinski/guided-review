## Risk: ADR-025, `--restricted` on Claude Enterprise is unproven

M3 is the first milestone where Claude reads teammates' code (plan, step analysis, questions). ADR-022's flags are proven only on PC/Max (S1–S3); field visit 1 (now at field visit 3, ADR-025) checks them on Claude Enterprise. If Enterprise refuses `--restricted`, every M3 task fails with `CLAUDE_FAILED` on the laptop.

Mitigation built into M3:
- Every new task (plan, step, ask) builds its argv **only** through `runner.rs` (`Task` + `read_only_args`); no other module touches flags. A new unit test fails if any `src-tauri/src/**` file other than `claude/runner.rs` contains `"--tools"`, `"--restricted"`, `"--permission-mode"` or `"--resume"`.
- `restricted_fallback_args` already exists (field probe only). Switching to it is a new ADR plus a change in `runner.rs`; M3 adds no second switch point.
- Argv snapshot tests for plan, step and ask (streaming + `--resume`) pin the profile.
- Unverified on Enterprise and rechecked at field visit 3: stream-json + `--resume` under `--restricted` (S1 PC/Max only), managed settings that could block Read/Grep/Glob, the default model under "Same as Claude Code". RUNBOOK-1 already covers the profiles; the plan adds no field step.
- Also unproven (ADR-024/025): `diffHeadSha` (decision 7) and `/discussions` on-prem. Both are verified on the stand-in (17.11.7) first; `gr-probe gitlab read` gets them as key-set rows so field visit 3 checks them.

## Decisions (approved)

1. **Thread cards in M3.** The S-03 PNGs show inline thread cards with Resolve/Reply, but F-11 is M5. Proposal: M3 shows the gutter thread icon (F-07.5) and read-only thread cards (avatars, author · age, text, replies) as step context (F-06.9); Resolve/Reply/Reopen arrive with F-11 in M5. Design-check notes the missing buttons as justified.
2. **Self-review note decisions (copy not in the spec).** Proposal: in self-review the primary action is **Keep to fix** (instead of Add to drafts), confirmation "Kept to fix. It's on your list at the end." Dismiss keeps its copy. **Edit and add** becomes **Edit and keep**. The summary heading stays "SUMMARY"; progress line "All 6 steps reviewed." / "4 of 6 steps reviewed."; empty list "Nothing to fix." Goes into 01 (F-17.2, F-17.4) and 02 (S-05).
3. **Mechanical rules (F-05.5; new 05 subsection, first match):** generated (`*.g.cs`, `*.g.i.cs`, `*.Designer.cs`, paths under `obj/` or `bin/`, or a first line containing `<auto-generated`) · whitespace-only (old and new lines equal after collapsing whitespace) · `.csproj`/`.props` package bump (every changed line is a `PackageReference`/`PackageVersion` whose only difference is `Version`) · `.resx` key additions (only added lines, all inside `<data name=…>…</data>` blocks). File-level hunks (F-05.7) stay skim proposals as today.
4. **Ask answers in Focus mode (no mock shows an answer).** Proposal: an answer card in the note-card style (purple Claude square, streamed text, follow-up input, **Add to drafts**, **Copy**). A and B: inline under the selected lines, or under the step header with no selection. C: in the guide panel above the ask input. B's **Ask Claude** and More › Ask Claude open it with the input focused. New S-03 state in 02.
5. **Already discussed.** Proposal: the summary text comes from Claude (`already_discussed`). Without Claude: "N open threads." from the discussions count. Threads load from GitLab when the plan runs and when a step opens; MR sessions only.
6. **F-09.5 enforcement.** Proposal: Claude gets the thread list (prompt rule, as `step.md` already says), and Rust does **not** filter by topic, because it can't judge topic deterministically. `npm run eval:claude` gets a golden case with a thread on a line that has a real issue. (Rejected alternative: drop any finding on the exact file/side/line of an unresolved thread; it hides different-topic findings.)
7. **"Plan is ready" (F-02.5).** Proposal: the GraphQL list adds `diffHeadSha` (ADR-024 update; verified on the stand-in by introspection, added to gr-probe). The row says it when a plan cache entry exists for that head under the current plan model/effort. Cached plans survive restarts in `claude_cache`.
8. **Detailed mode toggle in the title bar** (S-03 PNGs). Proposal: shown; Detailed opens the existing S-04 stub until M4; `Ctrl+D` comes with M4.
9. **Finish review in M3.** Proposal: self-review → self-review summary (F-17.4). MR sessions → the S-05 stub until M5, while drafts stay local.
10. **Resume cards without F-04.2.** The "N NEW COMMITS" tag and **Only new changes** are M8. M3 cards show **Continue** only; design-check justification.
11. **Demo.** The roadmap demo says "review !<real MR>". Per ADR-019 that is a synthetic MR on the stand-in (seeded MR with the fixture MAUI project) with the real `claude` on PC/Max.
