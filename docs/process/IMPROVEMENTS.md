# Process improvements

The feedback loop for how we build Guided Review (not the product). Data: `node tools/metrics/report.mjs` (ledger `.metrics/sessions.jsonl`, from the Claude Code transcripts; `.verify/timings.jsonl` for verify steps). `/retro` reads the numbers, judges the open experiments below, and adds at most three new ones. Every change to the process is an experiment with a metric and a baseline, so it can be kept or reverted on evidence.

Last retro: 2026-10-19T06:38Z (59 sessions)

Priorities (owner, 2026-10-16): quality, then time, then cost. Every experiment states its effect in this order and keeps the higher priorities as they are. At the end of every milestone `/retro milestone <Mx>` reviews the whole autopilot mechanism (retro skill step 4).

## Baseline (2026-10-13, 10 M3 sessions 3b–3e)

- Main thread: 55–132 turns, base context 53–54k, max context 150–243k (10 of 10 over 150k), cache read 6.5–26M per session (median ≈ 12M).
- Context tax: ≈ 84% of the top tax is reading files through the shell (`sed` 12.0M, `cat` 7.9M, `grep` 4.7M over 12 sessions).
- `/design-check`: 66 turns and 5.5M cache read per run (the pre-bd9897a skill: bd9897a was committed on the M2 branch after M3 branched and only reached M3 in dc775d4).
- Tool time over 12 sessions: verify 38 min, design-check 18 min, shell loops 16 min.

## Ideas

Candidate changes to the mechanism that are not experiments yet; every `/retro milestone <Mx>` re-ranks them (quality, then time, then cost) and starts at most two.

- 2026-10-16 · Review answers `testDispute` as an object (`{decision, why}`) while `prompt-lib.mjs` reads only `"accept"`: the F-11.3 fix prompt said "(none)" until the conductor rewrote review.json · ap-20261016-1738 F-11.3 (session card proposed).
- 2026-10-16 · A risk checklist per screen for the test author (virtualized rows remount, both layouts and line kinds, restored screen, renamed files): the severe findings of F-11.1, F-11.2 and F-11.3 were all in these classes · P-083, P-084, P-087.
- 2026-10-16 · The conductor pastes every role prompt into its own context (309k max in ap-20261016-1738): let the role read its prompt file instead, to keep the conductor small · metrics R11, session max context.
- 2026-10-19 · Conductor shell calls: `Bash: python` 22–50× per autopilot session in 5 sessions, `git status` 17–31×, `git diff` 18–30× (R2, R10): find what the conductor parses with python and give `backlog.mjs`/`judge.mjs` a subcommand that prints it · report --last 8.
- 2026-10-19 · Split items stay the slowest and least clean (E12 reverted: F-12.5 197.6 min, 6 gates, 3 severe): size them smaller in the planner (one IPC command and its screen as two criteria-sized items) rather than two passes of one implementer · E12 numbers.
